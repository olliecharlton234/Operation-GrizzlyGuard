Group 15 · Operation GrizzlyGuard

How to run each scenario

One command starts the sim, drone, patrol, YOLO, decision making and the bears. You choose which scenario to run.

Quick start

Already set up? Run this, changing the word after scenario:=. Use your own workspace folder if it's somewhere else.

cd ~/RS1-Workspace/Operation-GrizzlyGuard
source install/setup.bash
ros2 launch grizzlyguard_decision scenario.launch.py scenario:=red
ScenarioType thisWhat it shows
No bearscenario:=no_bearNormal patrol
Greenscenario:=greenBear noted, patrol continues
Yellowscenario:=yellowSound, follow to green, back to patrol
Redscenario:=redSpray, changes to sound, follow to green
Emergencyscenario:=emergencyCritical alert, follow the bear
Not a bearscenario:=not_a_bearPerson reported, patrol continues

E-stop, return home and manual run on top of any scenario, from the GUI. See GUI controls.

After you press enter

  1. Gazebo and the YOLO viewer open. The viewer window is called rqt_image_view, so check your taskbar if you can't see it.
  2. Wait for the drone to take off. Nav2 takes about 30–60 seconds to start.
  3. The drone hovers for 12 seconds to look for a bear, then starts its patrol.
  4. Decision messages print in the terminal, mixed in with lots of other output. For a clean view, open a second terminal and run:
source /opt/ros/humble/setup.bash
ros2 topic echo /perimeter/alert --field data

Press Ctrl-C in the launch terminal to stop, and wait for it to finish before starting another scenario.

Options

Add thisWhat it does
gui:=trueOpens the team GUI. It slows the camera a lot on a laptop, so only use it when you need it. See setup for building it.
rviz:=trueOpens RViz to show the map and planned path.
viewer:=falseDoesn't open the YOLO viewer.
route:=long_routeChanges the patrol route. The scenarios are placed for short_route, the default, so another route may not pass the bear.

First-time setup

You only need to do this once per laptop.

1. Get the code

cd ~/RS1-Workspace/Operation-GrizzlyGuard
git fetch origin
git switch main
git pull

2. Install what it needs

bash grizzlyguard_perception/scripts/install_onnxruntime.sh
sudo apt update
sudo apt install ros-humble-vision-msgs ros-humble-cv-bridge ros-humble-rqt-image-view
sudo apt install --only-upgrade ros-humble-diagnostic-updater

The last line fixes a crash in ekf_node saying libdiagnostic_updater.so is missing. Without that fix, the drone can't navigate.

3. Add the two YOLO models

Models aren't stored in git, so put both of these in grizzlyguard_perception/models/ before you build:

FileWhat it's forWhere to get it
bear_custom.onnxOliver's trained bear model. YOLO won't start without it.Oliver
yolo26n.onnxThe standard model, used to spot people. Without it, everything still runs, but hikers can set off false bear alarms.Ask Mahak or Oliver, or make it with scripts/export_yolo.py

4. Build

source /opt/ros/humble/setup.bash
colcon build --symlink-install
source install/setup.bash

5. The GUI (only if you want it)

Colcon no longer builds the GUI. You have two options:

  • Qt Creator: build and run it the usual way from the main README, alongside the launch command. Don't add gui:=true.
  • With gui:=true: the launch file looks for the program in build/grizzlyguard_gui/, so build it there first, then rebuild it whenever the GUI code changes:
source /opt/ros/humble/setup.bash
cmake -S grizzlyguard_gui -B build/grizzlyguard_gui
cmake --build build/grizzlyguard_gui -j4

The scenarios

Zones are measured by how far the bear is from town at (0, 0): green over 40 m, yellow 15–40 m, red 10–15 m, emergency 10 m or less. In each scenario, one bear walks in that zone and the others are hidden underground.

Times are roughly how long after Nav2 started in our test runs. They vary from run to run.

No bear

Worked in its latest run
ros2 launch grizzlyguard_decision scenario.launch.py scenario:=no_bear
What should happen

The drone takes off and patrols, with no follow and no deterrent. You'll still see "Person detected: not a bear" when it passes a hiker. That's correct, because hikers are on the map.

Green

Worked in 4 of 4 latest runs
ros2 launch grizzlyguard_decision scenario.launch.py scenario:=green
What should happen

The drone patrols. At around 80 seconds, it passes the bear, reports its location and keeps patrolling with no deterrent.

In the terminal
Bear in Green zone at (32, 37): Normal
Bear lost from view: returning to patrol

The second line just means the drone has flown past. It didn't stop patrolling.

Yellow

Latest 2 runs clean; 1 of 3 before that lost sight briefly
ros2 launch grizzlyguard_decision scenario.launch.py scenario:=yellow
What should happen
  1. The drone patrols, and YOLO spots the bear at around 55–65 seconds.
  2. The drone pauses its patrol and flies to within 10 m.
  3. It plays the sound, and the bear walks away from town.
  4. The drone follows until the bear reaches green, about 20–25 seconds later.
  5. The deterrent stops and the patrol resumes.
In the terminal
Bear in Yellow zone at (22, 17): Yellow
Deterrent deployed: sound
Bear in Green zone at (32, 26): Normal
Deterrent stopped

Sometimes the drone loses sight first and you'll see "Bear lost from view". It goes back to patrol, and usually spots the bear in green moments later.

Red

Latest 2 runs confirmed green; 1 earlier run ended on "lost"
ros2 launch grizzlyguard_decision scenario.launch.py scenario:=red
What should happen
  1. The bear is near the drone's start, so this begins within about 10 seconds of takeoff, during the 12-second hover.
  2. The drone sprays, and the bear walks away from town.
  3. When the bear enters yellow, the deterrent changes to sound.
  4. The drone follows until the bear reaches green, then goes back to patrol.
In the terminal
Bear in Red zone at (11, 4): High Priority
Deterrent deployed: spray
Bear in Yellow zone at (18, 2): Yellow
Deterrent deployed: sound
Bear in Green zone at (42, 6): Normal
Deterrent stopped

Green can get missed here too, ending with "Bear lost from view". The patrol still resumes.

Emergency

Worked in 4 of 4 latest runs with the GUI
ros2 launch grizzlyguard_decision scenario.launch.py scenario:=emergency gui:=true
What should happen

Within about 10–20 seconds of takeoff, the GUI opens a big red pop-up and the drone follows the bear. There's no deterrent, so the bear stays there and this doesn't end by itself. Stop it with Ctrl-C or the GUI's buttons.

In the terminal
BREACH:7

The number is how far the bear is from town. The pop-up says "left the perimeter", which isn't quite the right wording for this case.

Not a bear

Worked in 6 of 6 latest runs
ros2 launch grizzlyguard_decision scenario.launch.py scenario:=not_a_bear
What should happen

All the bears are hidden and four hikers walk around the map. The drone reports people and never stops patrolling.

In the terminal
Person detected: not a bear, continuing patrol

It only recognises people, not other animals.

If it goes wrong

What you seeWhat to do
Drone sits on the ground for over a minute, status stuck on WAITING FOR NAV2Nav2 hung during startup. It happens now and then, and it didn't happen in the final 11 test launches, but keep this in mind. Press Ctrl-C and launch again.
No boxes showingFind the rqt_image_view window on your taskbar. Its dropdown should say /parrot1/bear_detections/image. RViz's Camera panel shows the plain camera, with no boxes. Gazebo never shows boxes.
Viewer looks like a slideshowThat's normal. The whole system is heavy, so it may only update every second or so, and slower with the GUI open.
model file not foundPut the model in grizzlyguard_perception/models/, then run colcon build --symlink-install again.
ekf_node crashes, or libdiagnostic_updater.so is missingRun the last line from step 2 of setup.
TAKEOFF FAILEDThe altitude controller isn't running. The launch file starts it for you, so check you're using scenario.launch.py.
The drone sees the bear late, or not at allBears only get spotted within about 10–15 m, so stay on short_route, which the scenarios are placed for. Close the GUI if you don't need it, because it slows the camera.
gui:=true says BearDroneGUI not foundBuild the GUI first. See step 5 of setup.
Old windows still open, or strange behaviour after stoppingClose everything, including old terminals, then launch again.
Don't run these at the same time: this launch file, perimeter_status_node.py, and yellowstone_demo.launch.py from the integrated-demo branch. They send the same messages and would fight over the GUI and the bears.

Known limits

  • Small test counts. The results here come from a few runs each on one laptop, so rehearse on the laptop you'll present from.
  • Return home stops about 10 m from the start, at the same spot every run. That points to an offset between the drone's map and the world rather than random drift, but the cause isn't confirmed. Patrol routes may be offset the same way.
  • The drone can't go around trees while following. It stops if one's in the way, and the bear can walk out of sight behind one. The scenario spots are chosen to avoid this, but a bear elsewhere on the map may not get the same result.
  • False boxes still happen. YOLO sometimes boxes a tree near (26, 56), which can give a false green note. It takes three sightings to react, so most false boxes do nothing.
  • People, not animals. The person check only recognises people. If it misses a person, a hiker could still set off a false bear alarm.
  • The scare goes to every bear. YOLO can't tell bears apart, so "all" bears hear the deterrent. That's fine here, because each scenario has one bear out.
  • The GUI slows the camera, which makes detection weaker. Emergency has a 12-second hover after takeoff to allow for this.
  • Zones are measured from town. patrol_routes.yaml describes them from the drone to the nearest bear, and the team still needs to agree on one (Step 0 in the main README).
